📋 Fixed Config

ℹ️ Why a config fails on filtered mobile networks, and what the fixer changes
  • Fingerprint — unsafe sends Go's own TLS ClientHello. It only makes sense in PattNG together with custom cipher suites; on stock v2rayNG it is easy for DPI to recognise. The fixer sets a browser fingerprint (chrome by default).
  • Final Mask — streamSettings.finalmask is only understood by Xray-core 26+ (PattNG, recent builds). Older cores ignore it silently, so no fragmentation happens at all.
  • Classic fragment — adds a freedom outbound tagged fragment with packets / length / interval and points the proxy's sockopt.dialerProxy at it. Every Xray core since 1.8 supports this.
  • DNS loop — with sockopt.domainStrategy: UseIPv4 the core resolves the server domain through its own DNS; if that DNS query is routed through the proxy, the proxy can never connect. The fixer adds a direct DNS rule for the server domain.
  • Clean IP — replaces the server address and keeps SNI and the ws Host on the original domain, so a CDN still routes the request.
  • Test Pack — no single fragment value works on every network. The pack is a JSON array with one config per preset plus a no-fragment control, each with its own name. Import it (v2rayNG: Import config from clipboard), run the real-delay test, and keep the one that connects.

Working Templates

Rebuilds your config around one of two layouts taken from configs that connect on MCI. Paste your full JSON config or a VLESS / VMess / Trojan link — your server, UUID and transport are kept; DNS, routing, fingerprint and fragment come from the template.

—

🅰 Template A — single proxy, finalmask fragment, DNS pinned

Modelled on a working VLESS + REALITY config: chrome fingerprint, finalmask fragment 1-3 · 50-100 · 10-20 · maxSplit 10 plus UDP noise, UseIP with happy-eyeballs, the server domain pinned to its IP in dns.hosts (or resolved by a direct domestic DNS), and every domestic DNS routed direct. Finalmask needs Xray-core 26+ (PattNG / a recent v2rayNG).

🅱 Template B — several addresses, leastLoad balancer

Modelled on a working VLESS + ws + TLS CDN config: the same server reached through several addresses (CDN edges, clean IPs or other domains pointing at it), one balancer member each with chrome / edge fingerprints, leastLoad + burstObservatory to pick the fastest, a fallback member, Iranian DNS (Shecan / Begzar) for .ir domains and no core DNS for the server address. Only for TLS servers behind a CDN or with several reachable addresses.

📋 Template Config

ℹ️ What the two working configs do differently
  • No DNS loop. Both keep the proxy from waiting on its own DNS: the REALITY config pins the server domain to its IP in dns.hosts and routes every domestic DNS direct; the CDN config sets no sockopt.domainStrategy, so the system resolves the server address.
  • An SNI the filter lets through. REALITY borrows a big site's TLS identity (www.samsung.com); the CDN config fronts a different, unfiltered domain as SNI and routes on the Host header.
  • Redundancy. The CDN config tries several addresses at once and keeps the fastest one alive with an observatory.
  • Fragment is optional. The CDN config uses none; the REALITY config uses a finalmask fragment with maxSplit and UDP noise.
  • A template cannot change the server side: if your server's IP or domain is blocked, use template B with CDN addresses or clean IPs that reach the same server.

🕘 کانفیگ‌های اخیر (روی همین دستگاه)
ℹ️ چرا کانفیگ روی ایرانسل وصل است ولی روی همراه اول نه؟
  • فیلتر SNI. همراه اول نام دامنه را از بسته‌ی ClientHello می‌خواند. فرگمنت (finalmask) این بسته را خرد می‌کند. نسخه‌ی ۷ ابزار فرگمنت را حذف می‌کرد؛ نسخه‌ی ۸ مقدار کانفیگ سالم همراه اول را اضافه می‌کند (نیاز به Xray-core 26+ / نسخه‌ی جدید v2rayNG).
  • آی‌پی CDN مسدود. اگر دامنه پشت Cloudflare است، همراه اول ممکن است بازه‌ی آی‌پی‌ای را که دامنه به آن حل می‌شود ببندد. با آی‌پی تمیز، آدرس عوض می‌شود ولی SNI و Host همان دامنه می‌مانند.
  • DNS. حل کردن دامنه‌ی سرور با DNS خارجی (مثل 223.5.5.5) یا از مسیر خود پروکسی ممکن است روی یک اپراتور جواب ندهد؛ v8 آن را با DNS داخلی و مستقیم حل می‌کند.
  • یک کانفیگ برای هر دو اپراتور. balancer با burstObservatory هر دقیقه همه‌ی مسیرها را می‌سنجد؛ مسیر اصلیِ بدون فرگمنت (همان که روی ایرانسل کار می‌کند) همیشه fallback است.
  • اگر آی‌پی یا دامنه‌ی سرور روی همراه اول کاملاً مسدود باشد، هیچ تنظیمی در کلاینت کمک نمی‌کند — آی‌پی تمیز، دامنه‌ی جدید یا REALITY روی سرور لازم است.

Iran Relay — VLESS + WS + TLS

کانفیگ را به ساختار سه کانفیگی تبدیل می‌کند که روی همراه اول، ایرانسل و بقیه‌ی اپراتورها وصل‌اند: چند عضو VLESS + WebSocket + TLS که به سرور(های) رله داخل ایران وصل می‌شوند (هم با دامنه، هم با IP)، SNI یک دامنه‌ی پوششی، و Host یک برچسب کوتاه (مثل s1) که رله با آن سرور خارجی را انتخاب می‌کند؛ به‌علاوه‌ی یک مسیر پشتیبان مستقیم از Cloudflare. کانفیگ کامل JSON (full config) یا لینک vless:// پنل خودتان را بچسبانید یا فایلش را انتخاب کنید.

📋 کانفیگ نهایی

ℹ️ چرا این کانفیگ‌ها روی همه‌ی اپراتورها وصل‌اند
  • گوشی فقط به سرور داخل ایران وصل می‌شود. آدرس‌های اصلی دو سرور در دیتاسنترهای تهران‌اند؛ ترافیک داخلی از فیلتر بین‌الملل عبور نمی‌کند. رله ترافیک را به سرور خارجی می‌فرستد.
  • TLS با دامنه‌ی پوششی. SNI یک دامنه‌ی بی‌ربط است که گواهی‌اش روی رله نصب است؛ ALPN فقط h2 و fingerprint هر عضو فرق دارد.
  • Host کوتاه = انتخاب سرور خارجی. s1، s3، s5 روی رله به سرور هلند / آلمان / آمریکا نگاشت می‌شوند؛ مسیر و UUID برای همه یکی است.
  • بدون fragment. چون مقصد داخلی است، تکه‌تکه کردن لازم نیست.
  • انتخاب خودکار. balancer از نوع leastLoad با پینگ دقیقه‌ای؛ اگر همه‌ی رله‌ها قطع باشند، مسیر ecloud مستقیم از Cloudflare به سرور خارجی می‌رود.
  • DNS داخلی. شکن و بگذر برای دامنه‌های ایرانی، UDP 443 (QUIC) مسدود، تبلیغات مسدود، ترافیک ایران مستقیم.

Shadowsocks Relay

Rebuilds a Shadowsocks config in the layout of two configs that connect on every Iranian network: plain Shadowsocks (chacha20-ietf-poly1305, TCP) to a relay server inside Iran on a high port, its domain pinned in dns.hosts. Paste a full JSON config (or an array of them) or one ss:// link per line.

⚙️ Options

Paste a Shadowsocks config or link above to enable

📋 Shadowsocks Config

ℹ️ Why these Shadowsocks configs connect on every network
  • The server is inside Iran. Both relay domains point to IPs in Tehran. The phone only talks to a domestic server, so the international filter never sees the traffic; that server forwards it abroad (the configs are named 🇩🇪).
  • Plain Shadowsocks, AEAD cipher. chacha20-ietf-poly1305 over TCP, no TLS, no transport tricks, mux off, high ports (42124 / 52124).
  • No DNS on connect. The relay domain is pinned to its IP in dns.hosts.
  • Iranian traffic stays direct. .ir domains, geoip:ir and private ranges go out directly; the domestic DNS is routed direct too.
  • Shadowsocks straight to a foreign server is usually detected and blocked — the relay is what makes it work. The project guide explains how to build the relay in 3x-ui.

ℹ️ How Chain Proxy Works

A chain proxy routes your traffic through two proxies in sequence:

You → Config 1 (Worker/CDN) → Config 2 (Chain) → Internet

This fixes your outgoing IP address to the chain proxy's IP, ensuring a consistent IP for all destinations.

Supported Protocols

  • VLESS — vless://uuid@server:port?params
  • VMess — vmess://base64-json
  • Trojan — trojan://password@server:port?params
  • Shadowsocks — ss://base64(method:pass)@server:port
  • SOCKS — socks://user:pass@server:port
  • HTTP — http://user:pass@server:port
  • SSH — Sing-box only (4-field input: server, port, username, password)

Output Formats

  • Xray JSON — Use with any Xray-compatible client (v2rayN, v2rayNG, Nekoray, etc.)
  • Sing-box JSON — Use with sing-box client

Supported Transports

TCP, TCP (http header), WebSocket, gRPC, HTTPUpgrade

Supported TLS

TLS, Reality, None

⚠️ Important Notes

  • SOCKS & HTTP configs must include username and password.
  • Xray does not support raw (headerless TCP) configs.
  • Shadowsocks cannot have any transport (WebSocket, gRPC, etc.) and cannot have TLS.
  • SSH is only supported by Sing-box — Xray tab is disabled when SSH is used.

ℹ️ How the ECH Enhancer Works

Paste VLESS or Trojan URL(s) (one per line) and this tool adds:

  • fp — TLS fingerprint (default chrome, overrides the URL's own value).
  • ech — ECH Config List for Encrypted ClientHello. Use the ECH Server selector to pick a preset (default cloudflare-ech.com + Cloudflare udp://1.1.1.1); the field stays editable for manual tweaks. A bare domain (e.g. cloudflare-ech.com) auto-adds +udp://8.8.8.8; a base64 ECHConfigList is passed through untouched.
  • Server — IP/domain override, auto-filled from the pasted URL; empty to keep the original address.
  • Subscription Input — paste a subscription link to fetch it in your browser, or paste its contents (plain or base64) to batch-enhance every VLESS / Trojan config inside with the same ECH options below. The server override is ignored here — each config keeps its own address.
  • Output — Copy to clipboard, .txt download (one config per line), or base64 .txt download (standard subscription body).

ech is only added when the config uses tls security. Clear the field to skip it.

⚠️ TLS required: this tool only works with configs that have TLS enabled. Non-TLS configs are not supported and will not work.

Client Requirements

  • Xray — any recent core (v2rayN, v2rayNG, Nekoray, etc.).
  • Sing-box — version 1.13.0 or higher; Clash — version 1.19.20 or higher.

📋 Enhanced Configs

ℹ️ How the Enhancer Works

Paste VLESS or Trojan URL(s) (one per line) and this tool adds:

  • cs — TLS cipher suite list for the handshake.
  • fm — final mask / fragment settings (packet fragmentation for TLS handshakes). Use the Fragment Version selector to switch between v1 (classic) and v2 (new, default); the field stays editable for manual tweaks.
  • fp — TLS fingerprint (default unsafe, overrides the URL's own value).
  • Server — IP/domain override, auto-filled from the pasted URL; empty to keep the original address.

cs and fm are only added when the config uses tls security. Clear a field to skip that parameter.

⚠️ TLS required: this tool only works with configs that have TLS enabled (security tls or reality). Non-TLS configs are not supported and will not work.

Client Requirements

  • Windows — use PattN.
  • Android — use PattNG.
ℹ️ How Subscription Import Works

Paste a subscription link and this tool fetches it in your browser, then runs every config through the Fragment + Fingerprint options above.

  • Fetch — fetched directly in your browser (works when the provider sends CORS headers); if the provider blocks browser access, the link's content must be pasted manually. The error then shows 3 quick steps, and the Open link button next to Fetch opens the URL in a new tab for copying.
  • Pasted content — if the box holds a list of configs (or a base64 blob) instead of a link, nothing is fetched; the content is enhanced as-is. A saved subscription file can also be dropped onto the input card.
  • Decode — accepts both plain-text lists and base64-encoded subscription bodies.
  • Enhance — uses the fp / cs / fm values set in the options above. Fragment presets apply to TLS configs only. ECH is handled in the ECH tab and is not applied here.
  • Server override in the options above is ignored here — a subscription holds many servers, so each config keeps its own address.

Output Formats

  • Copy — clipboard, one config per line.
  • .txt — one config per line, ready for bulk import (v2rayNG, v2rayN, Nekobox...).
  • base64 .txt — the whole list base64-encoded, the standard subscription body format.

⚠️ Notes

  • Only VLESS and Trojan configs can be enhanced — others are counted as skipped.
  • Configs without TLS / Reality are exported but fragment settings are not applied to them.
  • If the fetch fails, the provider likely blocks browser access — open the link in a new tab and paste its contents straight into this box.
